Cara memakai panduan ini. Kerjakan berurutan. Setiap langkah ditutup kotak hijau "Berhasil kalau". Jangan lanjut sebelum tanda itu terlihat, supaya kalau ada masalah kamu tahu persis di langkah mana penyebabnya. Langkah 1 sampai 3 tidak butuh alat, jadi bisa dikerjakan sambil menunggu kiriman komponen.
SIARENG adalah alat pembelajaran. Ambang statusnya masih nilai awal untuk uji, bukan hasil kajian geologi, dan alat ini bukan sistem peringatan dini resmi. Untuk keadaan darurat, ikuti arahan BPBD setempat.

Cara kerja SIARENG

  1. Tiga sensor mengukur kelembapan tanah, hujan, dan pergeseran kemiringan.
  2. ESP32 membaca sensor 5 kali per detik, lalu memutuskan status: aman, waspada, atau bahaya.
  3. LED dan buzzer memberi peringatan langsung di lokasi. Bagian ini tetap bekerja walaupun internet mati.
  4. ESP32 juga mengirim datanya ke backend di laptop, yang menyimpan data dan meneruskannya ke dashboard serta Telegram.

1

Siapkan laptop

Tidak butuh alat · sekitar 1 jam

Pasang empat program ini. Semuanya gratis.

  1. Visual Studio Code: code.visualstudio.com
  2. Git: git-scm.com. Di Windows, biarkan semua pilihan bawaan saat memasang.
  3. Python 3.10 atau lebih baru: python.org/downloads. Di Windows, centang "Add python.exe to PATH" di layar pertama.
  4. Di VS Code, buka Extensions (Ctrl+Shift+X), lalu pasang:
    • PlatformIO IDE. Tunggu tulisan "Installing PlatformIO Core" di pojok bawah hilang (5–10 menit).
    • Wokwi Simulator. Tekan F1, ketik Wokwi: Request a New License, ikuti halaman yang terbuka.

Cek di terminal:

git --version
python --version
Berhasil kalau ikon kepala semut (PlatformIO) muncul di bilah kiri VS Code, dan kedua perintah di atas menampilkan nomor versi.

3

Coba tanpa alat

Tidak butuh alat · 30 menit

3a. Simulasi alat di Wokwi

  1. Di VS Code, File → Open Folder, buka SIARENG/firmware (bukan folder SIARENG).
  2. Klik ikon PlatformIO → Build. Build pertama lama karena mengunduh perkakas ESP32.
  3. Tekan F1 → Wokwi: Start Simulator.
  4. Putar potensiometer (tanah dan hujan) dan geser slider MPU6050. Skenario lengkap ada di docs/simulasi-demo.md.

3b. Dashboard mode demo

Klik dua kali file SIARENG/dashboard/index.html. Di bagian "Kendali demo", tekan Lereng bergerak. Setelah 2 detik panel besar berubah menjadi Bahaya dan muncul banner merah.

Berhasil kalau LED hijau menyala di simulasi Wokwi, dan saat tanah dibuat jenuh sambil kemiringan digeser, LED merah berkedip.

5

Rakit di breadboard

Butuh alat · 2–3 jam

Kuncinya: pasang satu komponen, uji, baru pasang berikutnya. Kalau semua dipasang sekaligus lalu ada yang salah, sulit mencari penyebabnya.

Yang perlu dipahami dulu

Kotak biru: 5 lubang dalam satu kolom pendek saling tersambung. Jalur panjang di tepi (merah = +, biru = −) tersambung sepanjang papan. Celah di tengah memisahkan bagian atas dan bawah.

  • Label pin ESP32 bisa tertulis D21, G21, IO21, atau 21. Semuanya berarti GPIO 21.
  • Cabut kabel USB setiap kali mengubah sambungan.
  • Semua sensor diberi daya dari pin 3V3, jangan dari VIN atau 5V.
  • Warna kabel di gambar hanya penanda. Kamu boleh memakai warna apa saja, asalkan sambungannya sama.

5.1ESP32 saja

  1. Tancapkan ESP32 melintang di atas celah tengah. Kalau papanmu versi lebar (38 pin) dan satu sisi tidak menyisakan lubang, pin di sisi itu disambung dengan jumper male-female langsung ke kaki ESP32.
  2. Buka firmware/include/config.h, ubah #define SIMULASI 1 menjadi 0.
  3. Colokkan USB. Di VS Code (folder firmware terbuka): PlatformIO → Upload. Kalau berhenti di Connecting....., tahan tombol BOOT di ESP32.
  4. PlatformIO → Monitor.

Port tidak terdeteksi? Lihat chip kecil di dekat port USB ESP32: CP2102 (pasang driver "CP210x" dari Silicon Labs) atau CH340 (pasang driver "CH340").

Berhasil kalau Monitor menampilkan {"event":"boot"} lalu MPU6050 tidak terdeteksi. Pesan error ini wajar karena sensornya belum dipasang.

5.2MPU6050 (kemiringan)

Colok USB lagi, lalu tekan tombol EN (atau RST) di ESP32 untuk memulai ulang.

Berhasil kalau pesan error hilang, muncul baseline_siap, lalu baris data tiap 2 detik. Saat breadboard dimiringkan, nilai tilt_delta_deg naik.

5.3Tiga LED

Kaki panjang LED (anoda) disambung ke resistor, ujung resistor lain ke GPIO. Kaki pendek (katoda) ke jalur biru. LED yang terbalik tidak rusak, hanya tidak menyala.

Berhasil kalau setelah restart, LED kuning menyala 2 detik (alat mengambil patokan kemiringan), lalu berganti hijau. Miringkan breadboard lebih dari 2°: setelah 2 detik LED kuning menyala.

5.4Buzzer

Berhasil kalau saat status waspada (breadboard dimiringkan), terdengar bip pendek tiap 3 detik.

5.5Tombol kalibrasi

Tancapkan tombol melintang di celah tengah breadboard. Pakai dua kaki yang berseberangan secara diagonal.

Berhasil kalau saat ditekan, Monitor menampilkan kalibrasi_ulang, dan posisi miring saat itu dianggap normal (LED kembali hijau).

5.6Sensor tanah

Bagian yang boleh basah hanya sampai garis putih di badan sensor. Komponen elektronik di bagian atas harus tetap kering.

Berhasil kalau nilai soil_raw berubah saat bagian bawah sensor digenggam atau dicelup ke air.

5.7Sensor hujan

Sensor hujan terdiri dari panel bergaris dan modul kecil. Sambungkan panel ke modul dengan dua kabel pendek bawaannya. Pin DO tidak dipakai.

Berhasil kalau nilai rain_raw turun saat panel ditetesi air. Rangkaianmu sekarang lengkap.
6

Kalibrasi sensor

Butuh alat · 30 menit

Setiap sensor sedikit berbeda, jadi alat perlu tahu angka "kering" dan "basah" milik sensormu. Lihat nilai soil_raw dan rain_raw di Monitor.

Yang diukurCaranyaIsi ke config.h
Tanah keringSensor dibiarkan di udaraSOIL_RAW_KERING
Tanah basahSensor dicelup air sampai garis batasSOIL_RAW_BASAH
Hujan keringPanel dilap sampai keringRAIN_RAW_KERING
Hujan basahSeluruh panel dibasahiRAIN_RAW_BASAH

Isi keempat angka di blok #else ("NILAI CONTOH untuk sensor asli") di firmware/include/config.h:

constexpr int SOIL_RAW_KERING = 3200;   // ganti dengan hasil ukurmu
constexpr int SOIL_RAW_BASAH  = 1400;
constexpr int RAIN_RAW_KERING = 4095;
constexpr int RAIN_RAW_BASAH  = 1200;

Upload lagi, lalu uji skenario bahaya: celup sensor tanah, miringkan breadboard lebih dari 5°, tunggu 2 detik.

Berhasil kalau soil_pct mendekati 0 di udara dan mendekati 100 di air, dan pada skenario bahaya LED merah berkedip serta buzzer berbunyi.
7

Sambungkan ke dashboard lewat USB

Butuh alat · 15 menit

Siapkan backend, cukup sekali. Buka terminal di folder SIARENG/backend-api:

python -m venv .venv
.venv/Scripts/pip install -r requirements.txt

Cari nomor port ESP32 di Device Manager → Ports (COM & LPT), misalnya COM5. Tutup Monitor PlatformIO karena satu port hanya bisa dipakai satu program. Lalu jalankan backend:

Git Bash:

SERIAL_PORT=COM5 .venv/Scripts/python -m uvicorn app:app --host 0.0.0.0 --port 8000

PowerShell:

$env:SERIAL_PORT="COM5"; .venv\Scripts\python -m uvicorn app:app --host 0.0.0.0 --port 8000

Buka http://localhost:8000 di browser.

Berhasil kalau pojok kanan atas dashboard bertuliskan "Menerima data dari alat", dan angka di layar ikut berubah saat sensor dibasahi atau breadboard dimiringkan.
8

Kirim data lewat WiFi

Butuh alat · 30 menit

Dengan WiFi, alat tidak perlu menempel ke laptop. Cukup beri daya dari adaptor atau powerbank.

  1. Cari IP laptop: jalankan ipconfig, catat angka di baris IPv4 Address, misalnya 192.168.1.10.
  2. Di firmware/include/, salin secrets.example.h menjadi secrets.h, lalu isi: 
    #define WIFI_SSID  "nama WiFi kamu"
#define WIFI_PASS  "kata sandi WiFi"
#define SERVER_URL "http://192.168.1.10:8000/api/telemetry"
#define API_KEY    ""
    File secrets.h tidak ikut ter-commit ke GitHub, jadi kata sandi WiFi tidak tersebar.
  3. Di config.h, ubah #define KIRIM_WIFI 0 menjadi 1, lalu Upload.
  4. Jalankan backend seperti Langkah 7. Bagian SERIAL_PORT=COM5 boleh dihapus.
  5. Saat Windows bertanya soal firewall, pilih Allow access.
Syarat WiFi: ESP32 dan laptop di jaringan yang sama, dan jaringannya 2,4 GHz (ESP32 tidak bisa 5 GHz). Hotspot HP bisa dipakai. Dashboard juga bisa dibuka dari HP di WiFi yang sama: http://192.168.1.10:8000.

Kunci API (disarankan). Isi kata kunci yang sama di secrets.h (API_KEY) dan saat menjalankan backend (API_KEY=kunci-kamu di depan perintah), supaya server hanya menerima data dari alatmu.

Berhasil kalau Monitor menampilkan {"event":"wifi","ip":...}, dan dashboard tetap menerima data setelah kabel USB dicabut dan ESP32 diberi daya dari adaptor atau powerbank.
9

Peringatan ke Telegram (opsional)

Butuh alat · 20 menit

  1. Di Telegram, buka @BotFather, kirim /newbot, ikuti petunjuknya, dan simpan token yang diberikan. Perlakukan token seperti kata sandi.
  2. Kirim pesan apa saja ke bot barumu.
  3. Buka https://api.telegram.org/botTOKEN/getUpdates di browser (ganti TOKEN), lalu cari angka setelah "chat":{"id":. Itu chat ID.
  4. Jalankan backend dengan dua pengaturan tambahan: 
    TELEGRAM_BOT_TOKEN=token-kamu TELEGRAM_CHAT_ID=123456789 \
  .venv/Scripts/python -m uvicorn app:app --host 0.0.0.0 --port 8000

Pesan dikirim setiap status berubah, dan saat alat berhenti mengirim data lebih dari 60 detik.

Berhasil kalau saat kamu memicu status waspada di alat, pesan masuk ke Telegram dalam beberapa detik.
10

Pasang di lapangan

Lihat panduan perakitan

Setelah semuanya bekerja di meja, lanjutkan ke docs/panduan-perakitan.md: pemindahan ke PCB, catu daya panel surya, box tahan air, dan pemasangan di lereng.

Di lereng, alat butuh WiFi untuk mengirim data: router atau modem 4G di dekat lokasi, atau hotspot HP yang ditinggal. Kalau lokasinya tanpa sinyal, alat tetap berfungsi sebagai alarm lokal lewat LED dan buzzer.

Minta izin pemilik lahan, beri tahu warga atau perangkat desa, jangan memasang saat hujan, dan pergi minimal berdua.
Berhasil kalau alat terpasang tegak di tiang, LED hijau menyala setelah tombol kalibrasi ditekan, dan dashboard menerima data dari lokasi.
